# Academic Paper Revision Guide

## 目的

学術論文を、読者が主張、根拠、方法、結果、限界を正確に理解・検証できる文章へ改善する。分野、投稿先、執筆言語、原稿の成熟度に応じて、論理構成、学術表現、一貫性、再現性、図表、引用、査読対応を体系的に点検し、新しいドラフトを書く・直す際に同じ指摘を二度受けないよう事前にセルフチェックする。

単なる英文校正に限定せず、次の観点を優先する。

1. 主張が明確で、根拠によって支えられているか
2. 研究課題、方法、実験、結論が一貫しているか
3. 第三者が方法と評価を理解し、可能な範囲で再現できるか
4. 過剰主張、情報の欠落、曖昧さ、重複がないか
5. 投稿先の要件と学術分野の慣習に適合しているか

## 基本原則

- 著者の意図、技術的意味、数値、引用を変えずに改善する。
- 根拠のない主張、実験結果、引用、書誌情報を新しく作らない。
- 情報が不足している場合は推測で埋めず、必要な確認事項を明示する。
- 文法的に正しい表現を機械的に置換せず、分野、対象読者、文脈に合わせる。
- 投稿規定、スタイルガイド、テンプレートが提供されている場合は、それらを一般則より優先する。
- 原稿の変更範囲を守る。局所修正を依頼された場合は、無関係な箇所を全面改稿しない。
- 変更によって断定の強さ、因果関係、不確実性が変わっていないか確認する。

## 作業開始時に確認する情報

利用可能な範囲で次を把握する。不明な項目が作業を妨げない場合は、合理的な既定値で進め、採用した前提を示す。

- 対象箇所: 論文全体、節、段落、査読回答など
- 作業目的: 新規執筆、内容レビュー、英文校正、短縮、査読対応など
- 研究分野と想定読者
- 投稿先と書式・文字数・語数の制約
- 執筆言語と英語の変種（American English / British English）
- 保持すべき用語、記号、LaTeXコマンド、引用キー
- 希望する出力形式（修正文のみ、変更対照、理由付き指摘など）

## レビューの優先順位

表層的な英文修正より先に、重大な問題を確認する。

1. **正確性**: 数値、式、参照、主張と結果に矛盾がないか
2. **論理**: 研究課題から結論まで推論がつながっているか
3. **完全性**: 評価や再現に必要な情報が揃っているか
4. **構成**: 情報が適切な節と順序に配置されているか
5. **一貫性**: 用語、記号、時制、略語、単位が統一されているか
6. **表現**: 文法、語法、明瞭性、簡潔性が適切か
7. **体裁**: 投稿規定、引用形式、図表形式に適合しているか

重大な内容上の問題を、流暢な表現で覆い隠さない。

## 1. 論理と説明

査読において「わからない」という指摘は最も重く、繰り返されやすい。読者（査読者）が評価できるレベルまで噛み砕いて説明する。

### 1.1 主題を先に示す

段落と文では、可能な限り次の順序を使う。

**対象・主題 → 主張または観察（挙動・性能） → 根拠・理由 → 含意**

読者が「何について述べているのか」を理解する前に、性能、理由、例外を提示しない。述べたいことの対象を明確に伝えてから、その挙動・性能や理由を述べる（そうしないと、読者は何を言っているのか理解できない）。段落の先頭では、その段落が担う役割を明確にする。

構造テンプレート: **[何について述べるか] → [その挙動・性能] → [理由]**

### 1.2 主張と根拠を対応させる

- 各主張について、実験結果、引用、理論、観察のどれが根拠かを確認する。
- `significant` は、統計的有意性を意味する場合と「重要」を意味する場合を区別する。
- 相関関係から因果関係を断定しない。
- 一つの実験から適用範囲を超えて一般化しない。
- `prove`, `guarantee`, `always`, `best` などの強い表現は、根拠が十分な場合に限る。
- 不確実な結果には `suggest`, `indicate`, `may`, `is consistent with` など、証拠の強さに合った表現を使う。

### 1.3 「何を」「どのように」「なぜ」を書く

手続きや設計を列挙するだけでなく、理解または評価に必要な理由・操作の動機を説明する。ただし、理由が自明な操作まで冗長に説明しない。

- 何を処理・比較・測定するか
- どのような手順・条件で行うか
- なぜその設計・操作・指標・条件を選ぶか（例: 異なる粒度の出力間でのサイズ調整理由や、特定の性質を持たせる利点など）
- その選択が結果の解釈にどう影響するか

### 1.4 用語と略語を定義・統一する

- 専門用語、独自用語、ドメイン用語、略語は初出時に定義する。新しい用語を使うときは、**初出箇所で1文の定義を必ず置く**（用語を別名へ統一した場合でも定義の明示は必須）。
- 略語は原則として `full term (ABBR)` の形式で導入する。
- 広く定着した略語を定義するかは、分野と投稿先の慣習に従う。
- 一度しか使わない略語は導入しない。
- 一般語を独自の意味で使う場合は、その意味を明示する。
- 同義・類似の構成要素名（例: 同じ役割のモジュールを指す複数呼称）は、ドキュメント全体でどちらか一方に統一する。
- 粒度・単位の異なる概念（例: 画像領域、要素、単位セルなど）の混同を避け、指している対象がどれかを毎回確認する。
- 機構名と動作名の使い分けを意識し、区別する。

### 1.5 限界と適用範囲を明示する

結果が成立するデータ、条件、仮定、評価設定を示す。考察では、既知の限界、潜在的な交絡要因、一般化可能性への制約を、主張を不必要に弱めない範囲で説明する。

## 2. 論文全体の構成

各節の役割を混同しない。投稿先の構成規則がある場合は、それを優先する。

### Title

- 研究対象、主要な方法または貢献が伝わるようにする。
- 過剰に広い表現、未証明の優位性、不要な略語を避ける。
- 検索可能性を考慮し、分野で一般的なキーワードを使う。

### Abstract

原則として次を簡潔に含める。

1. 背景または研究課題
2. 既存研究の不足または目的
3. 提案・方法
4. 主要な評価条件
5. 主要結果（可能なら代表的な数値）
6. 結論または意義

本文にない結果や主張をAbstractへ追加しない。背景説明だけで語数を使い切らない。

### Introduction

- 課題の重要性を示す。
- 関連研究との差分または未解決点を具体化する。
- 本研究がその不足へどう対処するか説明する。
- 貢献を検証可能な形で列挙する。
- 「初めて」「最先端」などの新規性・優位性の主張には十分な調査と根拠を要求する。

### Related Work

- 文献を単に順番に要約せず、論点、方法、仮定、限界などで整理する。
- 既存研究を公平に説明し、本研究との差分を具体的に示す。
- 引用されていない一般化や、実際に確認していない文献内容を作らない。

### Method

- 入力、出力、前提、処理手順を明示する。
- 図、本文、数式で同じ構成要素の名称を統一する。
- 実装詳細と概念的説明を区別する。
- 読者が全体像を把握できる説明を、細部や数式より先に置く。

### Experiments / Evaluation

- データ、分割、前処理、比較手法、評価指標、実装、学習・推論条件を明示する。
- 公平な比較に必要な条件差を説明する。
- ハイパーパラメータやモデル選択に検証データを使ったか示す。
- 反復回数、乱数、分散、信頼区間、統計検定は、分野の慣習と主張に必要な水準で報告する。

### Results

- 事実として観察された結果と、その解釈を区別する。
- 最良結果だけでなく、研究課題に関係する重要な傾向や失敗も扱う。
- 本文、表、図の数値が一致しているか確認する。
- 絶対差と相対差を混同しない。percentage と percentage point を区別する。

### Discussion / Conclusion

- 結果が研究課題へ何を示すか説明する。
- AbstractやResultsをそのまま繰り返さない。
- 適用範囲、限界、今後の課題を区別する。
- 実験で支持されていない新しい主張を結論で導入しない。

## 3. 数式・記号・単位

- 未定義記号を残さない。数式に現れる全記号を、初出時または式の直前・直後で定義する。
- 添字、上付き、集合、座標系、次元の意味を一貫させる。添字の役割は Method 冒頭などで定義し、以後ぶれさせない。
- 局所座標を全体の範囲で合計するような、局所座標系と全体座標系の混同を避ける。
- 同じ記号を異なる意味で再利用しない。
- スカラー、ベクトル、行列、集合の表記規則を統一する。
- 数式の前に目的と直感を説明し、後で結果の意味を説明する。特に複雑な部分は、式の前に1〜2文で直感的説明を置き、記号の洪水を避ける。
- 本文の説明と式の演算・意味（例: 何の確率間・量間の計算か）が一致するか確認する。
- 単位、桁数、丸め方、有効数字を統一する。
- 変数と単位を区別し、投稿先や分野の表記規則に従う。
- 不要に複雑な式は分割するが、厳密性に必要な式を説明文だけに置き換えない。

## 4. 図・表・参照

- 図表は本文を読まなくても、キャプションと凡例から主要な意味を理解できるようにする。
- 本文では図表の全数値を繰り返さず、重要な傾向と解釈を述べる。
- 行、列、軸、記号、色、誤差範囲、単位を定義する。
- 図表を本文中で参照し、参照順と番号を確認する。
- キャプション、本文、図表内で用語と数値を一致させる。
- 色だけに依存せず、印刷、縮小、色覚多様性を考慮する。
- 比較条件や太字の意味を明示し、公平でない視覚表現を避ける。

表を説明する場合は、定義を先に書き、原則として次の順序にする。

1. 表が何を比較するかを1文で述べる
2. 各行・各列ラベル、指標、条件の定義を述べる
3. 主要な観察を述べる
4. その解釈または研究課題との関係を述べる

テンプレート:

> Table X compares [N] [対象] at [条件]. [ラベル1] stands for ... [ラベル2] stands for ... The [列名] column shows ... As shown in Table X, [結果の解釈].

## 5. 実験・データ・再現性

### 5.1 データ

- データの出所、収集方法、対象、規模、ライセンスまたは利用条件を必要に応じて示す。
- 学習・検証・テスト分割を誰がどの単位・基準で作成したか（配布元が提供したのか、著者が分けたのかを含めて）説明する。
- `split` は「均等に分ける」印象を与えることがあるため、特定の単位ごとに分ける場合は `data group` や `divide ... according to the [unit]` のような表現も検討する。
- データ漏洩や重複を防ぐ方法を示す。
- 除外基準、前処理、欠損値処理、アノテーション方法を説明する。
- test set だけが特別な特徴を持っているように読める書き方を避ける。long-tail などのデータ分布・統計的性質は、データセット全体の性質として述べるか、test に限る理由を明示する。
- 倫理、同意、プライバシー、バイアスに関する要件を分野の規則に従って扱う。

### 5.2 比較と評価

- 評価指標を定義し、その選択理由を必要に応じて述べる。
- baselineとのデータ、前処理、計算資源、モデル選択条件の差を明示する。
- 実験上の設計判断（例: なぜ validation set で checkpoint を選ぶのか、なぜ特定の評価指標や試行回数を選んだのか）について、選択の根拠を1文添え、意味が伝わるよう補足する。
- ablation studyでは、一度に何を変えたかを明確にする。
- test setを調整やモデル選択に使っていないか確認する。
- エラー分析では、代表例だけで一般的傾向を断定しない。

### 5.3 再現性

研究の性質と公開可能性に応じ、次を確認する。

- ソフトウェア、ライブラリ、バージョン
- ハードウェアと計算条件
- ハイパーパラメータ、乱数seed、停止条件
- 学習・推論時間または計算量
- コード、データ、モデル、補足資料の入手方法

非公開情報や匿名査読で伏せるべき情報を誤って開示しない。

## 6. 学術英語と明瞭性

### 6.1 文を明確にする

- 主語と主要動詞を近づける。
- 一文に複数の独立した主張を詰め込みすぎない。
- 長い名詞修飾・形容詞の連鎖が読みにくい場合は、前置詞句や関係節に分解する。名詞＋形容詞が3つ以上連鎖したら、前置詞句 (`in`, `for`, `of`) に分解する。「名詞句が長くないか？形容詞と名詞が組み合わさっていないか？」を毎回確認する。
- `this`, `it`, `they`, `which` の指示対象を明確にする。
- 受動態を一律に避けず、行為者が重要なら能動態、手続きや対象が重要なら適切に受動態を使う。
- 名詞化が連続する場合は、具体的な動詞へ戻せないか検討する。
- `a +数値` のような表現は使わない。前後を文としてつなぐ。

### 6.2 語と動詞を文脈で選ぶ

学術英語で一般的な語を一律に禁止しない。例えば `report`, `protocol`, `significant`, `novel`, `robust` は適切な文脈では使用できるが、意味と根拠を確認する。同時に、査読者から誤解や違和感を持たれやすい語については、以下の目安と置換候補を文脈に応じて検討する。

#### 意味と根拠を確認する語

- `report`: 結果を報告する意味では一般的。手法の説明や査読者が `report` を避ける傾向にある文脈では `describe` や `present` が適切な場合もある。
- `protocol`: 実験、通信、医療など、定められた手順・規約（相手のある規約）を指す場合に使う。単なる方法・手順なら `procedure`, `method`, `rule` を検討する。
- `significant`: 統計的有意性なのか、実質的な大きさ・重要性なのかを明確にする。
- `novel`: 何が既存研究と異なるかを具体的に示す。
- `robust`: どの変動、ノイズ、条件に対して頑健なのかを示す。
- `improve`, `outperform`: 比較対象、指標、条件、差の大きさを明示する。

#### 査読指摘を受けやすい語・動詞の置換目安（文脈に応じて検討）

| 見直す語・表現 | 置換・改善候補 | 理由・注意点 |
|---|---|---|
| `protocol`（単なる手順・方法） | `procedure`, `method`, `rule` | 通信手順のように相手がある規約と感じられることがある |
| `report`（動詞、手法説明など） | `describe`, `present` | 結果報告以外では不自然に感じられる場合がある |
| `diagnostics` / `diagnostic` | `examinations`, `examines`, `results` | 健康・医療の印象を与えたり、意図が伝わりにくかったりする |
| `removes` | `does not care about` | 文脈に応じて |
| `is`（定義文） | `consists of` | 構成を述べるとき |
| `used`（重み共有） | `shared` | 重み共有を述べるとき |
| `The present (paper)` | `This (paper)` | |
| `are` | `show` | 結果が「示す」とき |
| `is handled` | 具体的な主語＋動詞に | |
| `initialize` | 目的語を明示（目的語がないなら `start` を検討） | |

一般的でない可能性がある語は使うか再検討する。

### 6.3 接続関係を正確にする

- 原因: `because`, `since`, `due to`
- 対比: `however`, `whereas`, `in contrast`
- 条件・例外: `if`, `unless`, `except when`
- 結果: `therefore`, `thus`, `as a result`

接続語だけで論理を作らず、前後の命題が実際にその関係を持つか確認する。`unless` は「もし〜がなかったら」という条件付けであり、「〜でないので」という理由付けの意味で使わない（理由付けには `because ... not` を使う）。

### 6.4 時制を統一する

分野と投稿先の慣習を優先しつつ、一般には次を目安とする。

- 論文が現在提示している内容: present tense
- 実施した実験・観察: past tense
- 確立した知識や一般的事実: present tense
- 先行研究: 文脈と分野慣習に応じて present tense または past tense

### 6.5 簡潔にする

- 同じ内容を2回述べていないか確認し、重複文は統合または削除する。
- 同じ主張をAbstract、Introduction、Results、Conclusionで必要以上に反復しない。
- 段落先頭の要約文と後続の詳細文が同じ内容なら統合または削除する。
- 図表のキャプションと本文の役割を分け、表や図を説明する文が直前のキャプションや本文と重複していないか確認する。
- Related Work や Method で既に述べている内容を実験節などで繰り返していないか再評価し、不要な文は削る。
- `It should be noted that`, `It is important to mention that` など、内容を増やさない導入句を削る。
- 簡潔化によって条件、例外、根拠を失わない。

## 7. 引用と研究倫理

- 引用が主張を実際に支持しているか確認する。
- 一次資料が利用できる場合は、二次資料だけに依存しない。
- 引用キー、著者名、年、番号の不一致を確認する。
- 引用の存在や書誌情報を推測で作成しない。
- 逐語引用、言い換え、図表の再利用について、引用と許諾の要件を守る。
- 関連する反証研究や競合研究を不当に省略しない。
- 二重投稿、自己盗用、著者資格、利益相反、AI利用開示などは、投稿先と所属機関の規則に従う。

## 8. 査読コメントへの対応

### 8.1 コメントを分類する

各コメントを次のように整理する。

- 内容の正確性または追加実験
- 説明不足または構成
- 表現・文法
- 図表・数式・引用
- 投稿規定
- 誤解に基づく指摘
- 相互に矛盾する指摘

### 8.2 回答の構成

各コメントに対して次を含める。

1. 査読者への謝意
2. 指摘への直接回答
3. 実施した変更または変更しない理由
4. 変更箇所（節、ページ、行など）
5. 必要に応じて修正後の本文

回答例:

> Thank you for this helpful comment. We agree that the original description did not clearly define the evaluation setting. We have added the definition and clarified the selection procedure in Section X (page Y, lines Z–Z). The revised text reads: “...”

### 8.3 同意しない場合

- 防御的な表現を避ける。
- コメントの懸念を言い換え、理解していることを示す。
- データ、本文、投稿規定、スコープなどの根拠を示す。
- 可能なら、誤解を防ぐため本文を改善する。
- 実施できない追加実験については、制約と代替対応を具体的に説明する。

査読者の提案を無条件に採用せず、研究の正確性と一貫性を保つ。

## 執筆・推敲ワークフロー

**執筆・推敲時は必ず全観点（論理・実験記述・構成/冗長性・一貫性・表現）でセルフレビューする。**

### Step 1: 制約を確認する

投稿規定、対象箇所、変更範囲、用語、出力形式を確認する。

### Step 2: 内容監査を行う（論理・実験記述）

研究課題、貢献、主張、根拠、方法、結果、限界の対応を確認する。矛盾や不足を先に列挙する。

- 新出用語・ドメイン用語に定義があるか、未定義記号がないか、各主張に「対象→挙動・性能→理由」の順序があるか確認する。
- データ分割・実験設定・設計判断に主体と理由が書かれているか確認する。

### Step 3: 構成と冗長性を修正する

節、段落、文を、読者が必要な情報を順に得られる配置へ整える。

- 重複文・不要文がないか確認する。
- 表の説明で定義を先に書いているか確認する。

### Step 4: 一貫性を確認する

用語、略語、記号、座標系・添字、数値、図表参照、引用、時制、単位を全文で照合し、ぶれがないか確認する。

### Step 5: 表現を改善する

意味と証拠の強さを保ったまま、文法、語法、明瞭性、簡潔性を改善する。長い名詞句、避けるべき語・動詞の選択、接続詞の誤用がないか確認し、文脈に応じて置換目安を適用する。

### Step 6: 変更後に再検証する

- 局所修正が他の節、Abstract、Conclusion、図表、数式、査読回答との不一致を生んでいないか確認する。
- 査読対応では、変更が査読コメントの該当箇所を解消しているか、コメント原文と照合する。

## 出力形式

依頼内容に指定がなければ、作業に適した形式を選ぶ。

### 原稿の修正

1. **修正版**
2. **主な変更点**
3. **要確認事項**（情報不足、技術的判断、引用確認など）

### レビュー

重要度順に示す。

- **重大**: 正確性、論理、再現性、結論に影響する問題
- **中程度**: 理解、一貫性、評価可能性を損なう問題
- **軽微**: 文法、語法、体裁、任意の改善

各指摘には、対象箇所、問題、理由、具体的な修正案を含める。同じ原因の軽微な指摘はまとめ、重要な問題を埋もれさせない。

### 査読対応

コメントごとに、`Comment`、`Response`、`Changes in the manuscript` を対応付ける。変更していない事項も省略せず回答する。

## ガイドの更新方針
