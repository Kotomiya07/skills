# Documenting with Sources

外部情報源から引用するMarkdown文書の共通規約。サーベイ報告、論文解説など、外部から取得した事実を扱うあらゆる成果物に適用する。出典付き成果物を生成する他スキル（`survey`、`paper-details` など）から参照される。

## 1. すべての事実主張に出典を付ける

成果物内のすべての事実主張には出典を付けなければならない。出典のない主張は検証できず、文書化された知見として無価値である。情報源に紐付けられない主張は、明示的にその旨を記す（例：「出典未確認」）。出典のない主張を黙って紛れ込ませてはならない。

## 2. 参照形式

- 文中参照は `[label (YYYY/MM), location]` の形式をとる。
  - `label`: 情報源の識別子。埋め方（媒体名、著者略称、対象論文なら位置情報のみ、など）は呼び出し元スキルが決める。
  - `(YYYY/MM)`: 年と月。日は含めない。年のみ判明している場合は `(YYYY)` を使う。
  - `location`: 引用箇所が情報源のどこにあるか（`p.4`、`Section 3.1`、`Figure 2`、`(15)`、`opening`、`final paragraph` など）。特定できない場合は省略する。
  - `location` がない場合は `[label (YYYY/MM)]` と書く。
- `[1]` や `[2]` のような裸の番号参照を使ってはならない。番号だけでは読者が番号の意味を知るために本文と出典一覧を行き来せざるを得ず、可読性が落ちる。本文中で対象を直接識別できるラベルベースの形式を使う。

## 3. 引用と地の文の分離

- 要約だけでは執筆者の情報源の読み方が正しいか読者が判断できない。原文を併置することで、読者が執筆者の解釈を情報源そのものと照合できる。
- 引用と地の文（執筆者自身の要約や解釈）は視覚的・構造的に分離しておく。引用していないときでも、情報源の主張と執筆者の解釈が混ざらないように書く。
- 外部情報源の引用は、内容の種類を問わず——文章、プロンプトテンプレート、コード、XMLタグ付きテキストなど何であれ——常にフェンス付きコードブロック内に入れる。引用記法（`>`）を使ってはならない。
- 執筆者の作業言語以外の言語で書かれた情報源を引用するときは、同じコードブロック内に原文と訳を並べて配置する。
- 引用ブロックの詳細な構造（空行区切り、出典参照の配置位置）、具体例、プロンプトテンプレート訳でのロール表記短縮、6つのアンチパターン、および呼び出し元スキルごとの適用範囲は [references/quotation.md](references/quotation.md) に従う。引用ブロックの執筆・編集前に必ず確認する。

## 4. 根拠のない関連付け・解釈の禁止

情報源自体に含まれていない解釈、推測、関連付けを書いてはならない。

- 情報源が述べていないのに「これはXに関連する」「Yに応用できる可能性がある」「Zを示唆する」といった結び付けを捏造してはならない。
- 周囲の会話や呼び出し元プロジェクトの文脈を文書本文に持ち込んではならない。情報源の記述は、その情報源自身の内容の範囲内にとどめなければならない。
- 良い例: 「主な批判: ラベルを反転しても精度が必ずしも下がらず、テキスト勾配は古典的な勾配降下法とは数学的に異なる」（情報源が実際に述べていることを記述している）。
- 悪い例: 「AI文章改善との関係: フィードバックに基づく改善は勾配降下法と数学的に異なり……」（情報源はそのように述べておらず、会話文脈から関連付けを捏造している）。

## 5. 出典一覧の形式

文書末尾の出典一覧は次の形式を使う。

`[label, YYYY/MM] Author. "Title." Publication. URL`

`- [n]` のリスト形式を使ってはならない。
