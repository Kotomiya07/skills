# 研究発表の設計・練習・登壇ガイド

学会・研究会・学位審査・ゼミなどの研究発表を準備するときに読む。スライドの見た目・タイトルの付け方・1スライド1データ・図形の基本は `references/academic-presentation.md` を参照し、本ファイルはその前後（全体設計・各スライドの運用的配慮・発表練習・本番と質疑応答）を補う。

出典: 森畑暁政「For Better Research Talk（良い発表をするために）」（東京大学 森畑研究室、2019–2022、https://www.graco.c.u-tokyo.ac.jp/labs/morihata/presentation_memo.htm ）。内容は要約・再構成したものであり、原文の転載ではない。

前提: 発表に唯一の正解はなく、分野の慣習・会場環境・発表者自身の適性によって適切なやり方は変わる。本ガイドの内容も、自分に合わない部分は無理に採用しなくてよいという著者の立場を前提に使う。

## 1. 前提（聴衆との格差と発表の種類）

- いつ読むか／何を確認するか: 発表準備に着手する最初に読み、想定する聴衆レベルと「この場で伝えるべき内容」を決める。

### 発表スタイルの選び方と発表者の適性

- 明確な失敗はあるが唯一の正解はない。コミュニティの慣習や会場条件（プロジェクタの明るさ、声の通りやすさ、直前の発表の雰囲気）に応じてスタイルを調整する。
- 自分に合っていそうな上手い発表の要素を取り入れ、分かりにくい発表の要因を避けて自分の型を作る（普段受ける授業なども参考になる）。
- 発表の出来は「発表者のパフォーマンス」と「資料の質」の掛け算で決まる。聴衆に合わせる原則は、発表者自身が話しやすく意欲を保てる範囲で適用する（例: 自分が話しやすくなるなら、色やアニメーションを通常よりやや多めに使う判断もあり得る）。

### 発表者と聴衆の格差を前提に置く

- 発表者と聴衆の間には、次の6つの格差が本質的に存在する前提で設計する。
  - 知識: 聴衆はその話を初めて聞くか、過去に聞いていても忘れている。
  - 見通し: 聴衆はこれまでの展開も忘れかけており、先の展開を知らない。
  - 理解: 聴衆は聞きながら処理しており、直前までの内容も完全には理解できていない。
  - 態度: 聴衆は受動的で、雑音など発表外の要因に気を取られやすい。
  - 動機: 聴衆は必ずしも聞く動機が高くなく、別のことを考えていることもある。
  - コンディション: 寝不足・時差・自分の発表準備などで万全とは限らない。
- 誰が聴衆であっても、期待より前提知識や集中力が低い層を基準に準備する（例: 指導教員には隣の研究室の教員に、他研究室の教員には他研究室の同輩に説明するつもりで組む）。
- 専門性や関心が高い層にとって多少平易でも致命的な問題にはなりにくく、むしろ前提認識のすり合わせに役立つ。

### 発表の種類ごとに「伝えるべき内容」を定める

- 「発表者が話したい内容」ではなく、「聴衆が聞きたい内容」と「発表者が伝えるべき内容」のズレを縮める。
- 伝えるべき内容は発表の性質で決まる。
  - 論文採択後の学会発表: 技術的詳細の網羅ではなく、研究の面白さを伝えて「論文を読みたい」と思わせる。
  - 卒論・修論審査: 成果の報告そのものより、正しい手順で研究に取り組み、自分の実施内容を理解していることを示す（成果が出ることは必ずしも求められない）。
  - 指導教員との定例ミーティング: 場合によっては先行研究の細部まで正確に理解していることの説明が求められる。

## 2. 全体設計（スライドを作る前）

- いつ読むか／何を確認するか: 1枚目のスライドを作り始める前に読み、材料の洗い出し・総枚数の見積もり・ストーリー構成の検証を済ませる。慣れるまでは、頭から1枚ずつスライドを作り始めない。

### 手順1: 材料の列挙

- 最初にストーリーを度外視し、発表に使える材料（複数の動機、研究の流れ、結果の解釈など）をすべて列挙する。後から取捨選択して1本の筋に絞る。

### 手順2: スライド枚数の計算と配分

- タイトルスライド等すべてを含めた総枚数は、次の目安で見積もる。
  - 10分程度の発表: 発表時間 ÷ 1〜1.5分
  - 15〜30分程度の発表: 発表時間 ÷ 1〜2分
  - 長い発表（概ね60分以上）: 発表時間 ÷ 1.5〜3分
- どのスライドも1枚あたり最低30秒をかける（高橋メソッド等の例外を除く）。30秒未満だと聴衆が少しよそ見をしただけで見落とし、スライド切り替えが多いほど内容を忘れやすくなる。
- 逆に1枚あたりの時間が長すぎる場合は、情報過密か、スライドに書いていない重要情報を口頭だけで補っている兆候であり、聴衆が聞き逃すと復帰しにくい。
- 発表時間が長いほど1枚あたりの持ち時間を延ばし、単位時間あたりの密度を下げて聴衆の疲労を防ぐ。
- スライド作成前にパート別の割合（例: 導入20%・手法40%・実験結果20%・関連研究やまとめ等20%、内容により調整）を決め、時間配分とスライド枚数の両方を押さえる。

### 手順3: ストーリー仮組みとバランス確認

- 各スライドにキーワード・キーメッセージを1行ずつ割り当て、次の優先順で確認する。
  1. 時間内に収まるか: 全体および各パートの枚数が適正か。時間超過は聴衆の感情を損ねるため最優先で防ぐ。
  2. 伝えるべき内容が入っているか: §1で定めた発表の目的に照らし、必須要素が抜けていないか。
  3. 一本道の一貫性があるか: 実際の研究経緯が複雑でも発表では刈り込み、各スライドが「直前のスライドのみ」から理解できるようにする（それより前の内容は忘れられる前提）。
  4. 具体性があるか: 正確だが抽象的な説明より、多少不正確でも具体的な説明を優先する。具体例を置く位置を設計段階で決めておく。
  5. 難易度の波が適切か: 聴衆全員が同意・理解できる内容から入り、最終的に未知の領域へ到達させる。難しい領域に長居せず、難易度を上げたらすぐ平易な内容へ戻す波を作る。
  6. 緊張感を調整できているか（慣れたら意識）: 難しい・真剣な内容を連続して聴けるのはスライド3枚程度までとし、3枚に1枚程度は難しくない・気楽に聞ける内容を混ぜる。

### 導入部・本題・不採用材料の扱い

- 導入部は「問題・疑問を背景や見通しとともに示して興味を引く」「導入だけ聞いても発表の要旨が分かる」の2点を満たす。これらを満たすなら短いほどよく（1〜2枚でも可）、導入が長くなる場合は2段階に分けてまず分かりやすい中間目標まで到達させる。
- 本題は分量と難易度が膨らみやすいため、説明するか迷うトピックは削る。トピックを絞ったうえで選んだ範囲はある程度深く説明し、完全な理解を強いるより聴衆が納得感を持って追える水準を目指す。
- 本筋から外れた材料の扱い方を選ぶ。
  - 関連研究や今後の課題に絡めて言及し、全体像への伏線を残す。
  - 別途論文がある場合、予想がつく追加実験や専門的細部（定式化・証明など）は「時間の都合上割愛する」スライドで存在だけ示す。
  - 過去の発表資料や練習で削ったスライドは質疑応答用の補助スライドに回す。意図的に穴を残して質問を誘うやり方は、質問が来ないリスクや質疑時間の圧迫になるため勧めない。
  - 出す必要がなければ何もしない（削ったままにする）。

## 3. 各スライド

- いつ読むか／何を確認するか: 全体の骨組みに沿って各スライドを作成するときに確認する。初回で完璧を目指さず、発表練習で直す前提で組む。

### スライド間の繋がりと情報量

- 作成中にスライドの中身が設計時のキーメッセージからずれていないか、前後との繋がりを点検する。
- スライド間の接続は原則として「順接」にする。先行研究の欠点を挙げるなど話の展開上明らかな逆接（`academic-presentation.md` の背景→課題のつなぎ等が該当）は使ってよいが、それ以外の逆接は聴衆の予測から外れて負荷が高いため重要な場面に温存する。いずれの逆接を使う場合も、手前のスライドで利点と限界を併せて示すなどして次が逆接になることを予告しておくと展開を追いやすい。
- 情報が薄いスライドは前後との統合を検討する。情報過多のスライドは2枚に分割するより内容を削る方がうまくいきやすい。重要なスライドほど情報量を減らすのが理想だが、厳格に縛られなくてよい。
- 聴衆が説明を聞き逃しても追いつけるよう、スライド単体を見て意味が分かる程度の文章を書く。
- 文字サイズの pt 目安は `academic-presentation.md` を参照し、そのうえで会場の最後列から容易に読めるかを確認する（数式の添字なども見落とさない）。読む必要のない細部を小文字で置かない（自分用の覚書はメモ機能を使う）。複雑さを絵として示す目的なら、読む気が起きないほど明確に小さくする。

### 色・フォント・アニメーション・図表

- 色: 色覚特性のある聴衆やプロジェクタの発色劣化を前提に、色が分からなくても理解できる構成にする（色が必要な場合はユニバーサルデザイン等を参照する）。黄色・ライトパープルなど見えにくくなりやすい前景や、黒潰れしやすい濃い赤・濃い青の背景は避ける。
- フォント: 文字の区別は色よりフォントの違いを優先する。概念の種類（地の文・数式・プログラムなど）でフォントを分け、同一の概念は常に同じフォントで貫く（数式内の変数を地の文で参照する場合も揃える）。読みにくい装飾的な書体は避け、線が細いフォントは太字の活用を検討する。
- アニメーション: 見えない情報が生まれて見落としを招くため、原則控える（特に1行ずつの逐次表示は避ける）。使う場合は「1枚に収めざるを得ない多めの情報を順に整理するとき」「聴衆の注意が確実に集まる核心部分」「見落としても影響のない演出」に限り、ステップ数を最小化する。
- 図・表・グラフ: 図表で説明できる内容は原則図表にする。図だけで意味が通らない場合は短い補足文を添え、表・グラフを載せたスライドは説明時間が長くなりすぎないか、説明するつもりのない要素が含まれていないかを確認する。

### ジョークと特定スライドの扱い

- ジョーク: 滑るリスクに加え、受けても発表が止まり直前までの内容を聴衆が忘れるリスクがある。使うなら導入や小休止のつかみに限り、具体的な説明の途中には入れない。
- タイトルスライド: 1枚最低30秒の原則を当てはめ、タイトルの言い換えや自己紹介など平易な内容で30秒ほど説明する（難しい話は入れない）。30秒話せる情報がないタイトルは再検討する。
- 目次スライド: 目次だけのスライド（特にタイトル直後）は避ける。30分程度までの発表は目次なしで追えるストーリーにし、構成を示す必要がある場合も導入の終わりに流れの一部として説明する。長い発表の進捗図も、全体プランは導入後に示す。
- 最終スライド: 「ご清聴ありがとうございました」だけのスライドは作らない（`academic-presentation.md` 参照）。聴衆は直前のスライドしか覚えていないため、情報のない1枚を進めると発表内容を忘れさせ、質問が出にくくなる。
- 小休止: 話題の切れ目に小休止を置く。長い発表では「ここまでのまとめ」等のスライドを用意し、短い発表でも5〜10秒程度の区切り（水を飲む・息を整える等）をどこに入れるか作成時に決めておく。

## 4. 発表練習

- いつ読むか／何を確認するか: スライドの形ができた段階から本番当日までに読み、練習スケジュールとスライド改修の観点を確認する。

### スケジュールと回数（3段階）

- 寝かせる期間を確保するため、スライドは発表の1週間前、可能なら2週間以上前に形にする。
- 発表練習は聴衆なしでもよく、次の3段階に分けて最低4回、基本は10回以上行う。
  1. 作成直後（確認）: 意図通りに作れているかを一通り読み上げて確かめる（スライドを作りながら読み上げてもよい）。
  2. 寝かせた後（構成検証）: スライドを最低1晩、可能なら1週間程度寝かせ、制作時の意図を忘れた状態で本格的に通してストーリーの妥当性を確かめる。
  3. 仕上げ（通しの練習）: スライド修正後に話し方を固める（スクリプトを作るならこの前）。コンディションが悪い状態でも崩れないよう、発表前日の就寝前と発表当日の起床直後の最低2回は行う。
- 第1・第2段階の目的はすらすら話すことではなく、すらすら話せるスライドへ直すことにある。話しにくい箇所や時間超過は練習不足ではなく情報過多・構成不良を疑い、スライドの削除・追加・順序変更で対処する（非母語での発表では特に重要）。

### 練習時のチェック項目

- 各パートが設計時の時間配分どおりに話せているか（練習と本番では時間がずれるのが普通［著者の例では本番の方が5〜10%程度短くなる］ため、スライド単位の細かな秒数には過度にこだわらない）。
- 各スライドの繋がりが自然で、原則として順接になっているか。
- 説明が面倒・無駄と感じる箇所がないか。
- 説明せずに飛ばしてしまう要素がスライドに残っていないか。
- スライドに書いていない内容を口頭だけで説明していないか。
- アニメーションが説明のテンポを妨げていないか。
- 小休止を入れるタイミングが明確か。

## 5. 本番と質疑応答（オンラインの差分を含む）

- いつ読むか／何を確認するか: 発表直前の過ごし方、登壇中の姿勢と時間調整、質疑応答の原則、オンライン発表時の注意を確認する。

### 発表直前の過ごし方

- 導入部（タイトル〜1枚目）だけを重点的に確認し、緊張しても自然に出られるようにしておく。
- 会場内を歩く・飲み物を取る・伸びをする・関節をほぐす・会場を見渡すなどして緊張を解き、声が出る状態にする。
- 直前にスライドを頭から最後まで何度も見直さない（緊張が強まり、自分の世界に入って聴衆との乖離が広がる）。確認は冒頭や重要な繋ぎに絞る。

### 発表中に意識することと時間調整

- 発表中の意識は原則2点に絞る。
  - 大きな声を出す（最重要）: 声が小さいと他の要素が優れていても伝わらない。特に冒頭の第一声は意識して大きく出し、最前列ではなく一番遠くの聴衆へ届ける（声が小さい場合はマイクを活用する）。
  - 聴衆を見ながら話す: スライドに向かって話し続けない。常に目が合う必要や特定の個人を見る必要はなく、「聴衆に向かって話している」姿勢を示せればよい。余裕があれば楽しそうに話すことも意識する。
- 上記2点を満たしやすいため原則として立って発表する。デモ等で座る場合は必ずマイクを使い、意識的に顔を上げる。
- 言い間違いや多少の詰まりは気にしない。早口で流暢に話しすぎて聴衆を置き去りにする方が問題。
- 時間調整: 序盤〜本題は時計を気にしすぎず練習通りの流れを保ち、終盤（実験・関連研究・まとめ等）に入ったところで1度だけ時間を確認する。
  - 時間が足りない場合: 早口にせず、残りの内容の一部を省略して時間通りに終える（例: まとめを表示だけして説明を省く）。時間超過は絶対に避ける。
  - 時間が余る場合: 話し忘れた内容があれば終盤に絡めて補ってもよいが、無理は不要。分かりやすければ予定より短く終わっても問題ない。

### 質疑応答

- 質疑は聴衆の曖昧な理解や誤解に基づくことが多く、噛み合わなくても減点ではない。基本方針は「シンプルに正直に応対し、限られた質疑時間を有効に使う」。
- Yes / No で答えられる質問には Yes / No で答える。
- 質問は文字通りに受け取り、裏の意図や非難を深読みしない。
- 知らないこと・分からないことは正直にそう答える。質問の意図が分からなければ聞き返す。
- 相手が発表内容を理解していると前提にせず、必要なら発表内容をそのまま繰り返す。
- 話が長引きそうなら「後で個別に議論しましょう」と打ち切り、他の質問へ回す。
- 場面に応じた調整: 卒論・修論審査（個別議論に回せず試問への丁寧な回答が評価に関わる）、議論自体が主目的の場、質問者が先行研究の著者など専門家である場合は、簡潔さより正確さや議論の深掘りを優先する。それでも「誤解の可能性」と「質疑時間の貴重さ」は常に意識する。

### オンライン発表の差分

- 基本原則は対面と同じだが、聴衆が他事や割り込みで注意散漫になりやすく、反応も見えないため対面より難しい。特効薬はなく、発表自体の質を高めるしかない。
- マイク性能や着席発声により声の伝わり方が対面と異なるため、事前に自分の発表を録音して聴き直す（マイクが良ければ声量の弱点も補える）。
- 画面の発色がプロジェクタより良いため、対面より文字や図表を載せやすい利点はあるが、1枚の情報過多には引き続き注意する。
