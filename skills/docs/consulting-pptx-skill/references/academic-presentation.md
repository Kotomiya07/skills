# 学会発表デッキの作法（学会発表のときだけ）

学会・研究会などの研究発表デッキを作るときだけ読む。経営会議向けの規約（slide-rules.md）とぶつかる点は、このファイル側を優先する。通常のデッキやポスター（§10）には適用しない。

出典: 大西真駿「学会発表で役立つ発表スライド作成のヒント」（株式会社リバネス・中高生研究者向け資料、Speaker Deck 公開 2021-12-22、https://speakerdeck.com/mashun07/xue-hui-fa-biao-deyi-li-tufa-biao-suraidozuo-cheng-falsehinto ）。内容は要約・再構成したもので、本文の転載ではない。動機付けの説明は除き、実行できるルールだけを残した。

## 構成（ストーリー）

- 背景 → 課題 → 目的 → 着目点・仮説 → 手法 → 結果 → 結論 の順にし、スライド間を「つなぐ言葉」でつなぐ。
  - 背景の後: 「しかし、これまでは … のため … を説明できていなかった」
  - 課題の後: 「そこで、本研究は … を解明することを目的とした」
  - 目的の後: 「この目的のため、… という可能性を考え、検証した」
- 研究目的のスライドでは次の3点を必ず入れる。
  1. 何が課題・不明点として残っていたか、なぜ分かっていなかったか
  2. その課題を解くために立てた目的
  3. 目的のために何に着目し、何を予想し、何を調べたか
- 結果は実験の羅列にしない。各結果について「何のために行ったか → 結果 → そこから何が考えられるか」を添え、聴衆を結論まで案内する。発表はスライドの朗読ではない。

## タイトル

- 発表タイトルは分野名だけにしない（悪い例:「ミトコンドリアの研究」）。研究を一言で表す具体的な文にする（例:「ミトコンドリアを分解するオートファジーの仕組みに迫る」）。
- 各スライドのタイトルは項目名だけにしない（悪い例:「顕微鏡観察」「結果1」）。そのスライドの要約がタイトルだけ見て分かる一文にする（例:「Get1/2複合体は効率的なマイトファジーに重要である」）。slide-rules の「結論はタイトルに書く」と同じ方向で、学会発表では特に厳密に守る。
- 表紙には発表タイトルに加えて、発表者名・所属・学会名（会議名）を入れる。

## 情報量と図

- 1スライドに載せるデータは1つを原則にする。一度にデータを見せすぎない。
- 背景スライドは情報を絞る。百科事典的な項目の羅列は載せない。載せる図も原則1つに絞り、その発表の目的に必要なものだけ残す。
- 結果スライドは、図のすぐ近くに結論を短く書く。
- グラフは、軸が何か・単位・文字の大きさを確認する。不要な軸や装飾は消し、数字が会場で読める大きさにする。

## 最後のスライド

- 「ご清聴ありがとうございました」だけのスライドは作らない。情報のない一文で終わらせず、まとめ（結論）を示すスライドで終える。

## デザイン（図形）

- テーマカラーを先に決め、デッキ全体で統一する。
- 図形の四原則:
  1. 標準色より落ち着いた色を使う
  2. ブロック矢印は使わず、シンプルな線の矢印にする
  3. 枠線・影・グラデーションはなるべく消す
  4. 図形の形・大きさ・位置を揃える
- 悪目立ちする図形は使わない。

## 文字サイズとフォント（目安。固定値にしない）

- フォントサイズの目安: タイトル 32–36 pt、本文 18–24 pt。タイトルスライドはタイトル 36–40 pt 程度、名前 32 pt、所属 24 pt。
- 16:9 か 4:3 か、会場の画面でも変わるため、下限の目安として使う。slide-rules の 22 pt タイトル等の数値は経営会議向けの前提なので、学会発表ではこの目安を優先する。
- フォント候補: 日本語は源ノ角ゴシック／ヒラギノ角ゴ／メイリオ／游ゴシック、英数字は Arial か Helvetica。ただし成果物のフォントは使用環境とテーマ側の指定を優先し、この候補で置き換えない。

## 聞き手への配慮（仕上げのチェック）

- 自分には当たり前の専門用語が、聞き手にも当たり前か。
- 構成とデザインは聞き手の理解を助けているか。
- 載せる情報量は多すぎないか。
- 話す速度と1枚あたりの情報量は合っているか。
